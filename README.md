# HelloClient Headless Sidebar

Тестовое задание на переиспользуемую адаптивную навигацию с разделением
поведения, интеграции и прикладной разметки.

- [Исходное задание](https://helloclient.notion.site/HelloClient-28cc51068cd580409c8cff7e0eb65b7d)
- [Демонстрация](https://cptshell.github.io/hello_client_demo/)

## Главное архитектурное решение

Реализация состоит из трёх уровней:

```text
ApplicationMenu
labels + routes + icons
          ↓
RouterMenu
React Router integration + product styles
          ↓
Sidebar
headless behavior + semantics + accessibility
```

- `Sidebar.*` — независимые от Router и внешнего вида компоненты. Они отвечают
  за состояние, адаптивное поведение, семантическую разметку, ARIA атрибуты,
  управление фокусом и обработку взаимодействий.
- `RouterMenu.*` — продуктовая обёртка над `Sidebar.*`. Она скрывает React
  Router, внутренние идентификаторы, регистрацию маршрутов, стили Tailwind и
  доступность декоративных иконок.
- `ApplicationMenu` — прикладная JSX-разметка. В ней остаются только пункты,
  названия, маршруты и иконки.

Таким образом, бизнес-код не передаёт `value`, `entryValue`, `id`,
`onValueChange`, `asChild`, `Link`, хуки Router или классы Tailwind.

## Продуктовый API

Основное меню приложения собирается следующим образом:

```tsx
<RouterMenu>
  <RouterMenu.Group icon={<Archive />} label="Inventory">
    <RouterMenu.Item label="Products" to="/inventory/products" />
    <RouterMenu.Item label="Orders" to="/inventory/orders" />
    <RouterMenu.Item label="Suppliers" to="/inventory/suppliers" />
  </RouterMenu.Group>

  <RouterMenu.Item
    icon={<Settings />}
    label="Settings"
    to="/settings"
  />
</RouterMenu>
```

`RouterMenu` самостоятельно:

- получает текущий путь из React Router;
- рендерит `Link` для обычных пунктов;
- синхронизирует активный пункт и родительскую группу;
- определяет первый маршрут вложенной группы;
- не создаёт повторную запись в истории браузера;
- применяет итоговый дизайн и адаптивные варианты.

## Headless API

Нижний уровень можно использовать без React Router. Например, локальное
состояние подключается напрямую:

```tsx
const [value, setValue] = useState('profile')

<Sidebar.Root value={value} onValueChange={setValue}>
  <Sidebar.List>
    <Sidebar.Item value="profile">Профиль</Sidebar.Item>
    <Sidebar.Item value="notifications">Уведомления</Sidebar.Item>
  </Sidebar.List>
</Sidebar.Root>
```

`Sidebar.Root` поддерживает управляемый и внутренний режимы для `value`,
`expanded` и `openGroupId`. При необходимости внешний потребитель может связать
их с Router, `useState`, хранилищем приложения или `localStorage`. Сам headless
слой и `RouterMenu` не выполняют скрытых операций с хранилищем.

## Что реализовано по требованиям

**Выполнено: 8 из 8 требований + [дополнительная работа](#extrascope).**

1. **React, TypeScript и Tailwind CSS**

   Проект реализован на React со строгой типизацией TypeScript. Внешний вид
   собран через Tailwind CSS 4 и семантические CSS-переменные.

2. **Логика соответствует видео и макетам**

   Реализованы раскрытое и свёрнутое боковое меню для компьютера, встроенная
   вложенная группа, интерактивное всплывающее подменю, нижняя мобильная
   навигация и модальная нижняя панель. Поддерживаются активные состояния,
   анимации и прокрутка при переполнении.

3. **Меню описано через JSX**

   Структура объявлена компонентами `RouterMenu.*` и `Sidebar.*`. Массивов
   конфигурации, рекурсивного рендера или JSON-подобного описания меню нет.

4. **Удобная интеграция с внешним состоянием**

   Headless API поддерживает управляемое и внутреннее состояния. Продуктовый API
   скрывает всю Router-обвязку, а отдельный пример демонстрирует управление
   через обычный React `useState`.

5. **Headless UI**

   `src/shared/ui/sidebar` содержит поведение, семантику и доступность, но не
   импортирует React Router, Tailwind или библиотеку иконок. Итоговый внешний
   вид находится в `src/features/router-menu`.

6. **Интеграция с React Router**

   `RouterMenu` связывает путь, активный пункт, вложенную группу и историю
   браузера. React Router используется только в продуктовой обёртке и не входит
   в headless-компоненты. Прямые URL, перезагрузка, «Назад» и «Вперёд»
   синхронизируют состояние меню.

7. **Полезные комментарии**

   Комментарии оставлены только возле неочевидных решений: разделения владельца
   навигации между `Link` и кнопкой группы, а также жизненного цикла внутреннего
   реестра маршрутов.

8. **Мобильный вариант**

   При ширине меньше `768px` меню превращается в нижнюю навигацию. Пункты
   занимают доступную ширину, а при переполнении прокручиваются горизонтально.
   Вложенная группа открывается в модальной нижней панели с удержанием фокуса,
   блокировкой прокрутки страницы и учётом безопасной области экрана.

## Extrascope

Сверх основных требований реализовано:

- **Управление с клавиатуры.** `Tab` и `Shift+Tab` перемещают фокус, `Enter` и
  `Space` активируют подходящие элементы, `Escape` закрывает flyout или
  мобильную модальную панель.
- **Управление фокусом.** После закрытия временного интерфейса фокус
  возвращается к открывшему его элементу. Мобильная панель удерживает фокус до
  закрытия.
- **Доступность.** Используются нативные ссылки и кнопки, `aria-current`,
  `aria-expanded`, `aria-controls`, семантика модального диалога, видимый focus
  ring и минимальная интерактивная область `44 x 44px`.
- **Адаптивные представления.** Одна headless-логика управляет встроенной
  группой, flyout и мобильной модальной панелью без дублирования логики.
- **Reduced motion.** Движение отключается при
  `prefers-reduced-motion: reduce`.
- **Поведенческие тесты.** Проверяются состояния, обработчики, история Router,
  регистрация маршрутов, переходы между адаптивными режимами, жизненный цикл
  фокуса, flyout и мобильный dialog.

## Адаптивные режимы

| Условие | Представление | Вложенная группа |
|---|---|---|
| `width >= 768px`, меню раскрыто | Боковое меню `256px` | Встроенное подменю |
| `width >= 768px`, меню свёрнуто | Боковое меню `72px` | Интерактивный flyout |
| `width < 768px` | Нижняя навигация | Модальная нижняя панель |

При смене варианта временные интерфейсы закрываются. Состояние ширины меню
сохраняется в течение текущей сессии компонента, а активный пункт всегда
определяется текущим Router location.

## Архитектура

Проект использует сокращённую структуру по FSD:

```text
src/
├── app/
│   ├── config/                # Маршруты приложения
│   ├── providers/             # HashRouter и таблица маршрутов
│   └── ui/                    # ApplicationMenu и ApplicationShell
├── pages/                     # Страницы демонстрационных маршрутов
├── features/
│   ├── router-menu/           # Router integration и продуктовый дизайн
│   └── sidebar-demo/          # Независимый пример на useState
└── shared/
    ├── lib/                   # Универсальные hooks и utilities
    └── ui/sidebar/            # Headless sidebar primitives
```

Направление зависимостей: `app → pages → features → shared`.

## Запуск

Требования:

- Node.js `22.13.0` или новее;
- npm.

```bash
npm ci --registry=https://registry.npmjs.org
npm run dev
```

Приложение будет доступно по адресу
[http://localhost:5173](http://localhost:5173).
